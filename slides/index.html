O problema

Hospedeiros

eproc, PJe, SEI, Siga-Doc…

Cada um com DOM próprio, sessão própria, ciclo de vida próprio.

Aplicações externas

Apoia, Assis, NPS, ferramentas internas…

Cada uma com URL, autenticação e contrato próprio.

Sem mediação: N hospedeiros × M apps = N×M integrações

Com um barramento: N + M adaptadores

A ideia-núcleo

Acoplar por interface, não por implementação

// O botão "Resumir" NÃO pede "a Apoia".
// Pede alguém que implementa a interface:

interface IAICollaborator {
  readonly capabilityId: 'ai';
  beginSession(ctx: LaunchContext): Promise<SessionHandle>;
}

// O kernel resolve QUAL implementação está ativa.
// Trocar Apoia → Assis é 0 linhas de mudança no botão.

Este é o único acoplamento: o nome da interface.

CapabilityBus — implementações

Registro central de proxies por chave ('case' | 'doc' | 'ai' | 'feedback').

class CapabilityBus {
  register<K extends CapabilityKey>(reg: CapabilityRegistration<K>): () => void;
  getActive<K extends CapabilityKey>(key: K): CapabilityOf<K>;
  listProviders(key: CapabilityKey): readonly { provider, priority }[];
  setActive(key, provider: string): void;
  onChange(listener): () => void;
}

// Producers publicam por interface:
bus.register({
  key: 'ai',
  provider: 'apoia',
  impl: new ApoiaAssistant(...),   // local
  // ou: transport: iframeTransport,   // remote (cria proxy lazy)
});

Vários producers por chave — prioridade decide o ativo. onChange reativa a UI.

AppRegistry — metadados + UI

Catálogo de apps conhecidos. Paralelo ao bus — o bus sabe "qual assistente está ativo", o registry sabe "que apps existem e como montar a UI".

interface AppDescriptor {
  readonly id: 'apoia' | 'nps' | ...;
  readonly name: string;
  readonly categories: readonly IntentCategory[];
  readonly capability: CapabilityKey;          // qual interface o app implementa
  readonly intents: readonly IntentDescriptor[]; // menu entries
  readonly ui: AppUi;                          // 'iframe' | 'react' | 'headless'
  readonly createAssistant: (cfg: AssistantConfig) => IInteractiveAssistant;
}

type AppUi =
  | { type: 'iframe'; urlBuilder, allowedOrigins, handshakeOnly? }
  | { type: 'react';  root: (props) => unknown }
  | { type: 'headless' };

Transporte · JSON-RPC 2.0 + postMessage

Envelope único, independente do canal:

// Request (host → app)
{
  "jsonrpc": "2.0",
  "id": "req-7c3a",
  "method": "ai.beginSession",
  "params": {
    "intent": "summarize",
    "documentId": "doc-1234",
    "user": { "id": "u-42", "name": "Maria" }
  }
}

// Response (app → host)
{
  "jsonrpc": "2.0",
  "id": "req-7c3a",
  "result": { "sessionId": "s-9912", "status": "ready" }
}

// Notification (sem id, sem response esperada)
{ "jsonrpc": "2.0", "method": "host.documentChanged", "params": { ... } }

Namespacing: method = capabilityId.action. createRpcProxy<T>() em @iagente/rpc transforma a interface TS no envelope.

ITransport — o canal que muda, o envelope que não

interface ITransport {
  send(envelope: JsonRpcEnvelope): void;
  onMessage(handler: (envelope: JsonRpcEnvelope) => void): () => void;
}

// Implementações:
class PostMessageTransport implements ITransport { ... }   // iframe / popup
class InProcessTransport  implements ITransport { ... }   // adapter local (testes, demo)

// O bus registra um transport:
bus.register({
  key: 'ai',
  provider: 'apoia',
  transport: new PostMessageTransport(iframe.contentWindow, 'https://apoia.pdpj.jus.br'),
});

// O CapabilityBus envolve o transport num proxy tipado
// que implementa a interface IInteractiveAssistant<T>.

Trocar de postMessage para WebSocket, SharedWorker, BroadcastChannel: nova classe, zero mudança no kernel.

Interfaces de domínio — o vocabulário

InterfaceLadoImplementado por
ICaseManagementSystemhosteproc, PJe, demo-host
IDocumentManagementSystemhostSEI, Siga-Doc

IFeedbackCollectorappNPS, avaliações

Cada interface traz um capabilityId que vira namespace JSON-RPC. Adicionar uma nova capacidade = nova interface + 0 mudanças no kernel.

De RPC para sessão interativa

Apps jurídicos não são funções one-shot. Têm setup → múltiplas trocas → finalize.

interface IInteractiveAssistant<T extends AssistantIntent = AssistantIntent> {
  readonly capabilityId: 'ai';
  readonly intents: readonly IntentDescriptor<T>[];

  beginSession(ctx: LaunchContext): Promise<SessionHandle>;
  // ^ setup: auth, carregar doc, abrir UI, handshake com iframe

  resumeSession?(handle: SessionHandle): Promise<void>;
  // ^ hot-reload: sobreviver a reload do host

  finalizeSession(handle: SessionHandle, result: AssistantResult): Promise<void>;
  // ^ teardown: gravar minuta, notificar host, fechar UI
}

type AssistantIntent = 'summarize' | 'review' | 'draft' | 'refine' | 'minuta' | 'chat';

UI shell · o que aparece no host

Floating button

32 px → 48 px no hover. Drag-Y com threshold de 4 px para reposicionar. Estado e posição persistidos.

Split pane

Sidebar que espreme o <body> via padding-right (não overlay). Handle arrastável, snap em ≤ 50 px = fecha.

App host

Renderiza iframe / react / headless. Cache escondido de iframes evita reload ao alternar.

CSS isolado em Shadow DOM — o estilo do host não vaza, o do iAgente não vaza para o host.

Isolamento × Coexistência

Shadow DOM

A árvore React do shell monta num shadowRoot. Estilos do host (Bootstrap, jQuery UI, Angular Material…) não alcançam a UI do iAgente.

Host squeeze

Em vez de overlay (z-index trap), o kernel injeta html.iagente-open { padding-right: var(--iagente-width) }. A página continua interativa — só fica mais estreita.

:host { all: initial; }
.iagente-fab { position: fixed; right: 0; width: 32px; ... }
.iagente-fab:hover { width: 48px; }   /* hover expand */
.iagente-pane { width: var(--iagente-width, 420px); }

Runtime · do <script> à UI montada

// packages/runtime/script-tag/src/entry.tsx
export function start(doc = globalThis.document) {
  const storage  = createLocalStorage();
  const bus      = new CapabilityBus();
  const registry = new AppRegistry();
  const orch     = bootstrap({ hostAdapters: HOST_ADAPTERS, bus });

  for (const app of APP_DESCRIPTORS) registerApp(bus, registry, app);
  applyPreferredApp(registry, bus, storage);

  const overlay = createOverlay({ document: doc });
  createRoot(overlay.root).render(
    <IagenteShell bus={bus} registry={registry} storage={storage} />
  );
  injectHostLayoutCSS(doc, overlay);
  return orch.session;
}

Saída: bundle IIFE de 1.7 MB minificado (React do NPS incluído) — serve de CDN ou é injetado por uma extensão de navegador.

Por que isto escala: N + M, não N × M

Acoplamento por classe

4 hosts × 3 apps = 12 classes tipo EprocApoiaAdapter, EprocAssisAdapter, PJeApoiaAdapter…

Acoplamento por interface

4 hosts × 3 apps = 4 + 3 = 7 adaptadores. Cada lado implementa só o que sabe; o kernel roteia.

Adicionar um novo app: 1 descritor + 1 implementação de IInteractiveAssistant. Nenhum host é tocado.

Adicionar um novo host: 1 HostAdapter + N implementações das interfaces expostas pelo host. Nenhum app é tocado.
